*codeviz.txt*                 Native CodeViz execution flow viewer

===============================================================================
1. Introduction                                                   *codeviz*

CodeViz asks the repository's TypeScript analyzer for an ExecutionModel and
shows a textual control-flow graph in a nofile split. Each semantic node shows
its deterministic node ID, source range, and explicit labeled outgoing edges.
Node IDs are not persistent across source edits.

The plugin implements the V1 schema only. It does not provide sequence views,
interactive graph expansion, or V2 behavior.

===============================================================================
2. Setup                                                    *codeviz-setup*

Add the `nvim` directory to 'runtimepath', then optionally configure:
>
  require('codeviz').setup({
    keymap = '<leader>vf',
    timeout = 10000,
    -- command = { 'node', '/path/to/codeviz/dist/cli/index.js', 'serve' },
    -- tsconfig = '/path/to/tsconfig.json',
    -- split = 'botright vnew',
  })
<
No global mapping is installed unless `keymap` is supplied. The default
analyzer command is:
>
  {'node', repository_root .. '/dist/cli/index.js', 'serve'}
<
===============================================================================
3. Commands                                                *codeviz-commands*

                                                        *:CodeVizFlow*
:CodeVizFlow
    Analyze the function under the cursor, including unsaved buffer text, and
    open or refresh the graph split.

                                             *:CodeVizExportMermaid*
:CodeVizExportMermaid [file]
    Request `exportMermaid` using the same source snapshot and analyzer model.
    With no file, open a nofile Mermaid buffer. Existing files are not overwritten.
    Destinations are fixed at invocation and created exclusively. Exporting a
    different source does not rebind an open graph. Obsolete export responses,
    including callbacks arriving after close, are ignored.

===============================================================================
4. Graph mappings                                         *codeviz-mappings*

<CR>        Jump to the selected node's precise source start.
<Tab>       Select the next semantic node.
<S-Tab>     Select the previous semantic node.
gd          Jump to a resolved call target, when available.
gr          Jump to source and invoke LSP references.
K           Show AST kind, source provenance, limitations and call details.
r           Refresh from the current unsaved source snapshot.
q           Close the graph and stop the analyzer job.

Moving the cursor in the source buffer highlights the smallest matching real
(non-synthetic) node in the graph. Source columns are converted between
Neovim byte offsets and the analyzer's one-based UTF-16 columns.
Navigation is blocked after source edits until the graph is refreshed.
This includes imported-definition jumps. Unsaved external target buffers must
be saved before navigating with disk-derived positions. Closing wipes the
graph buffer even when it is shown in duplicate windows.

===============================================================================
5. Protocol                                                *codeviz-protocol*

The analyzer uses JSON-RPC 2.0 messages separated by newlines over stdio.
`analyze` receives `{file, line, column, sourceText, tsconfig?}` and returns an
ExecutionModel with `schemaVersion = 1`. Requests time out, stale responses are
ignored, partial stdout chunks are retained, and pending requests fail if the
job exits.
